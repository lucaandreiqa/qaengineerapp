# Comment & move Jira ticket

These are visible, shared actions. YourQA shows the tester the exact comment before it is posted, and asks again before the ticket moves. Approving the comment never approves the move, and the other way round.

The skills under this one hold the detail: **QA summary comment**, **Remarks and worth knowing** and **Plain writing**.


## The comment

Build it from the checklist and the results: a concise summary in the format of QA summary comment, never a raw dump of the files. Report only what the run found.


## Moving the ticket

- Match the target status by its exact name against the transitions Jira offers for this ticket. Never guess or pick a similar name.
- When no matching transition exists from the current status, say which ones are available. Never force the status another way.
- When YourQA's move rules (in this skill, learnt from the statuses you chose before) name a status for the outcome, propose it; the tester still approves the move.
- Do not recommend the next status inside the comment.
